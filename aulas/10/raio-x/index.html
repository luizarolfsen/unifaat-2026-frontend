Jobs de um lado (fila + workers), notificações do outro (exchange + consumidores, cada um com a sua fila dinâmica). As funções recebem o nome do exchange por parâmetro.

O que muda

O exchange vira explícito: toda mensagem já passava por um (o padrão, ""); agora declaramos um fanout com nome.

Fila dinâmica

O subscribe cria uma fila exclusiva, sem nome, para este processo e a liga ao exchange: N consumidores = N filas no mesmo exchange.

Pegadinha

O rabbit.js guarda UM canal compartilhado; exclusive faz a fila sumir quando o processo cai. isConnected serve para o dispatch não fechar uma conexão que ele não abriu.

Etapa 2 · Event: a unidade do websocket

Event: createEvent e loadEvents

O equivalente do createJob e do loadJobs: a unidade nomeada e o loader que lê a pasta (e as subpastas por domínio).

src/utils/event.js
+ /**
+ * Event: a unidade de execução do entrypoint websocket (o equivalente do Job do worker).
+ * O name é o nome que viaja pelo WebSocket (socket.emit('chat:message', ...)).
+ * handle(payload, context): context traz o socket de quem enviou e notify(event, payload),
+ * que publica no exchange escolhido ao subir o entrypoint.
+ */
+ export function createEvent({ name, handle }) {
+ if (!name || typeof name !== 'string') {
+ throw new Error('Event precisa receber um name válido.')
+ }
+
+ if (typeof handle !== 'function') {
+ throw new Error('Event precisa receber um handle(payload, context) válido.')
+ }
+
+ return { name, handle }
+ }
src/utils/loadEvents.js
+ import fs from 'node:fs/promises'
+ import path from 'node:path'
+ import { pathToFileURL } from 'node:url'
+
+ /**
+ * Lê app/Events (e as subpastas, uma por domínio: Chat/, ...) e devolve um mapa: nome do Event → Event.
+ * É o equivalente do loadJobs: o entrypoint não conhece nenhum Event; Event novo = arquivo novo na pasta.
+ */
+ export default async function loadEvents(eventsPath) {
+ const entries = await fs.readdir(eventsPath, { withFileTypes: true })
+ const events = {}
+
+ for (const entry of entries) {
+ const fullPath = path.join(eventsPath, entry.name)
+
+ if (entry.isDirectory()) {
+ Object.assign(events, await loadEvents(fullPath))
+ continue
+ }
+
+ if (!entry.name.endsWith('.js')) {
+ continue
+ }
+
+ const eventModule = await import(pathToFileURL(fullPath).href)
+ const event = eventModule.default
+
+ if (!event || typeof event.handle !== 'function') {
+ continue
+ }
+
+ if (events[event.name]) {
+ throw new Error(`Event duplicado: ${event.name} (${fullPath})`)
+ }
+
+ events[event.name] = event
+ }
+
+ return events
+ }

Espelho do Job

createEvent e loadEvents fazem pelo websocket o que createJob e loadJobs fazem pelo worker.

O nome viaja

O name do Event é o nome que viaja pelo WebSocket (socket.emit('chat:message')).

node --check sem erro e o loadEvents('./app/Events') devolve ['chat:message'].

--exchange e --port, como o worker escolhe a fila com --queue.

Só conecta e distribui

Etapa 7 · Entrypoint websocket

Nginx: o túnel entra pelo container do nginx (upstream + /socket.io/)

O navegador continua falando só com o nginx (8080). Ele repassa o Upgrade e distribui as conexões entre as réplicas do websocket.

+ # réplica de nodewebsocket_host; o nginx resolve o nome na subida (réplica nova: nginx -s reload).
+ upstream websocket_servers {
+ # ip_hash; # sticky: só é preciso se o client usar polling; em sala de aula todos saem pelo mesmo IP
+ server nodewebsocket_host:3001;
+ }
+
server {
listen ${NGINX_PORT}; # Porta em que o NGINX vai escutar, vem do .env
...
try_files $uri.html $uri $uri/ @node; # Procura o arquivo estático => procura o diretório estático => senao vai para o bloco @node
}
+ # WebSocket (Socket.IO): repassa o Upgrade, a conexão fica aberta e o nginx escolhe a réplica na abertura do túnel
+ location /socket.io/ {
+ proxy_pass http://websocket_servers; # Container(s) do websocket, pela rede interna
+ proxy_http_version 1.1; # O Upgrade só existe no HTTP/1.1
+ proxy_set_header Upgrade $http_upgrade; # Pede a troca de protocolo para websocket
+ proxy_set_header Connection "upgrade"; # Mantém a conexão aberta para a troca
+ proxy_set_header Host $host; # Passa pra frente o host/nome do domínio
+ proxy_set_header X-Real-IP $remote_addr; # IP de origem: o chat mostra quem está online
+ proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; # Encadeia os IPs no cabeçalho
+ proxy_read_timeout 1h; # Túnel parado não é derrubado em 60 s
+ }
+
location @node {
proxy_pass http://nodeweb_host:3000; # "Passa" para o container Node na porta 3000 pelo protocolo HTTP

Upgrade

Sem Upgrade e Connection o handshake não chega ao Node e a conexão fica presa no polling.

Mesma origem

O io() do frontend não precisa de URL nem de CORS: é localhost:8080/socket.io/.

IP de quem conectou

X-Real-IP é o $remote_addr que o PRÓPRIO nginx viu: o websocket confia nele (o X-Forwarded-For pode vir inventado pelo client). Sem esse cabeçalho o websocket só enxerga o IP do container do nginx (::ffff:172.x): foi o que aconteceu com a imagem antiga, e o log do nginx mostrava o IP certo do celular o tempo todo. A imagem copia o template no build: precisa de docker compose up --build nginx-container. No Docker, quem acessa de localhost aparece com o IP do gateway da rede; outro computador da sala aparece com o IP dele.

upstream

É por ele que o nginx também entra na escalabilidade: com --scale nodewebsocket-container=3 o nginx reparte os túneis. O ip_hash fica comentado: em sala de aula todos saem pelo mesmo IP.

Conferido:

Túnel funcionando: o log do nginx mostra GET /socket.io/?EIO=4&transport=websocket → 101 do navegador e do celular. A imagem do nginx foi refeita (docker compose up -d --build nginx-container) e o nginx -t passou com o X-Real-IP no bloco /socket.io/.

Quem está online

O aoConectar também emite chat:join com o nome (e de novo ao reconectar); o presence:list chega pelo túnel e vira o estado online, desenhado embaixo com nome e IP.

Mensagem de sistema

O chat:joined ("fulano entrou na sala") entra na mesma lista, mas como outro tipo de item (kind: "join") e em outra cor (verde), diferente das bolhas dos participantes.

Nome na tela

O estado booleano isJoined troca o formulário do nome pela sala: o aoEntrar guarda o nome e liga o efeito do túnel.

Efeito com limpeza

O primeiro useEffect depende de [isJoined]: só abre o túnel depois de entrar; a limpeza tira os listeners e fecha a conexão, como na Aula 09.

Referências

O socket vive numa useRef (heap): mudar a conexão não renderiza. O fim da lista é um elemento do HTML para o scrollIntoView.

Botões de emoji

Cinco botões (🔥 💣 😉 💧 🎉) com um só handler, o aoClicarEmoji: ele lê o data-emoji do botão clicado e emite o emoji como mensagem, igual ao texto. Mensagem que é só emoji aparece maior.

Só volta pelo exchange

O aoEnviar emite e limpa o campo; a mensagem (inclusive a sua) só entra na lista quando o chat:message VOLTA do exchange.

Só WebSocket

io({ transports: ["websocket"] }) dispensa o polling e o sticky: o nginx reparte as conexões no revezamento.

Etapa 10 · Presença: quem está online

Quem está online e "fulano entrou na sala": a lista circula pelo exchange entre as réplicas

Cada réplica do websocket só conhece os sockets dela. Então cada uma publica a sua lista no exchange e guarda a das outras; o que o client recebe é a união de todas, com nome e IP. O aviso de entrada também vai pelo exchange.

+ import { randomUUID } from 'node:crypto'
+ import fs from 'node:fs'
+
+ const HEARTBEAT_MS = 5000
+ const EXPIRES_MS = 15000
+
+ /** IPv4 "limpo": tira o embrulho IPv4-mapeado (::ffff:1.2.3.4) e troca o ::1 do localhost por 127.0.0.1. */
+ export function normalizeIp(ip) {
+ const value = String(ip ?? '').trim()
+
+ if (value.startsWith('::ffff:')) {
+ return value.slice(7)
+ }
+
+ if (value === '::1') {
+ return '127.0.0.1'
+ }
+
+ return value
+ }
+
+ const IPV4 = /^\d{1,3}(\.\d{1,3}){3}$/
+
+ /**
+ * Gateway da rede do Docker (o computador que roda o Docker, visto de dentro do container): quem conecta
+ * DO PRÓPRIO computador chega ao nginx por ele, e o nginx só enxerga esse IP (ex.: 172.18.0.1).
+ * Lê a rota padrão do container em /proc/net/route (Linux); fora do Linux devolve null.
+ */
+ function dockerGateway() {
+ try {
+ const lines = fs.readFileSync('/proc/net/route', 'utf8').split('\n').slice(1)
+
+ for (const line of lines) {
+ const [, destination, gateway] = line.split('\t')
+
+ if (destination === '00000000' && gateway) {
+ return gateway.match(/../g).reverse().map((hex) => parseInt(hex, 16)).join('.')
+ }
+ }
+ } catch {
+ return null
+ }
+
+ return null
+ }
+
+ const GATEWAY = dockerGateway()
+
+ /**
+ * IP de quem conectou. Atrás do nginx, o X-Real-IP (o $remote_addr que o PRÓPRIO nginx viu) é o confiável: o
+ * X-Forwarded-For pode vir com um IP inventado pelo client. Sem proxy, vale o endereço do socket.
+ * Outro computador da rede: o IP real dele. O próprio computador do Docker chega pelo gateway: nesse caso o
+ * IP certo é o do PC na rede, que vem do host digitado no navegador (http://192.168.1.171:8080) ou do
+ * HOST_LAN_IP do .env (para quem entra por localhost).
+ */
+ export function ipOf(socket, gateway = GATEWAY) {
+ const headers = socket.handshake.headers
+ const forwarded = String(headers['x-forwarded-for'] ?? '').split(',')[0]
+ const ip = normalizeIp(headers['x-real-ip'] || forwarded || socket.handshake.address)
+
+ if (!gateway || ip !== gateway) {
+ return ip
+ }
+
+ const host = String(headers.host ?? '').split(':')[0]
+
+ if (IPV4.test(host) && host !== '127.0.0.1') {
+ return host
+ }
+
+ return process.env.HOST_LAN_IP || ip
+ }
+
+ /**
+ * Presença (quem está online) COMPARTILHADA entre as réplicas do websocket.
+ * Cada réplica só conhece os sockets dela: então publica a lista local no exchange (presence:instance) e guarda
+ * a lista das outras. A lista final é a união de todas. Uma réplica que cai some sozinha: sem batimento por 15 s,
+ * a lista dela expira. Quem só distribui eventos continua só distribuindo: aqui é só informação de conexão.
+ */
+ export function createPresence({ io, notify }) {
+ const instanceId = randomUUID()
+ const byInstance = new Map()
+ let lastSent = ''
+
+ const localUsers = () => [...io.sockets.sockets.values()]
+ .filter((socket) => socket.data.name)
+ .map((socket) => ({ id: socket.id, name: socket.data.name, ip: ipOf(socket) }))
+
+ const list = () => {
+ const now = Date.now()
+ const users = []
+
+ for (const [id, entry] of byInstance) {
+ if (now - entry.seenAt > EXPIRES_MS) {
+ byInstance.delete(id)
+ continue
+ }
+
+ users.push(...entry.users)
+ }
+
+ return users
+ }
+
+ // Só avisa os clients quando a lista mudou de verdade (o batimento repete a mesma lista)
+ const broadcastIfChanged = () => {
+ const users = list()
+ const json = JSON.stringify(users)
+
+ if (json === lastSent) {
+ return
+ }
+
+ lastSent = json
+ io.emit('presence:list', users)
+ }
+
+ const publish = () => notify('presence:instance', { instance: instanceId, users: localUsers() })
+
+ // Chegou a lista de uma réplica (inclusive a nossa, que volta pelo exchange)
+ const receive = (payload) => {
+ byInstance.set(payload.instance, { users: payload.users, seenAt: Date.now() })
+ broadcastIfChanged()
+ }
+
+ setInterval(() => {
+ publish().catch((error) => console.error('Erro ao publicar a presença:', error))
+ broadcastIfChanged()
+ }, HEARTBEAT_MS)
+
+ return { publish, receive, list }
+ }

Réplicas não se enxergam

Um io.emit só alcança os sockets daquela réplica. Para saber quem está online no total, a lista precisa viajar pelo mesmo exchange das mensagens (presence:instance).

Expira sozinha

Cada réplica manda um batimento a cada 5 s; se uma réplica cai, a lista dela some em 15 s. O servidor só avisa os clients quando a lista MUDOU.

Entrou na sala

O Event chat:join guarda o nome no socket (socket.data), pede a publicação da presença e publica chat:joined: o aviso chega a quem está em qualquer réplica.

O próprio PC

Quem conecta do computador que roda o Docker chega ao nginx pelo GATEWAY da rede (ex.: 172.18.0.1): o nginx não vê o IP de rede dele. O websocket lê a rota padrão do container (/proc/net/route) para saber qual é o gateway; se o IP recebido é ele, a conexão veio do próprio PC e o IP mostrado passa a ser o do PC na rede: o host digitado no navegador (http://192.168.1.171:8080) ou o HOST_LAN_IP do .env (para quem entra por localhost). Outro computador, mesmo numa rede 172.x, continua com o IP real.

IPv4 limpo

normalizeIp tira o embrulho ::ffff: e troca o ::1 por 127.0.0.1; ipOf prefere o X-Real-IP (do nginx) ao X-Forwarded-For (spoofável).

Separado do resto

A presença mora em utils/presence.js; o _websocket.js só liga as peças (etapa 4).
