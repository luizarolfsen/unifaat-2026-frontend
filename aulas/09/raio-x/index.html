Etapa 1 · Custom hook

useAxios: os estados da requisição num hook

Uma função use... que guarda data, error e isLoading e faz o GET num efeito. Quem chamar o hook herda os três estados: quando o hook chama setData, o componente renderiza de novo. A limpeza do efeito usa o AbortController para cancelar a requisição que ficou velha.

src/resources/js/hooks/useAxios.ts
+ import { useEffect, useRef, useState } from "react"
+ import { isCancel } from "axios"
+ import clientApi from "../api/_clientApi"
+ import { getErrorMessage } from "../utils/getErrorMessage"
+
+ // O que o hook conta para quem quiser acompanhar: começou, foi cancelado, chegou, falhou
+ export type AxiosEvent = "start" | "abort" | "done" | "error"
+
+ type UseAxiosResult<T> = {
+ data: T | null
+ error: string
+ isLoading: boolean
+ refetch: () => void
+ }
+
+ /**
+ * Custom hook: GET com Axios + os três estados da requisição.
+ *
+ * Os estados (data, error, isLoading) nascem AQUI, mas pertencem ao componente
+ * que chama o hook: quando o hook chama setData/setError/setIsLoading, quem
+ * renderiza de novo é o componente.
+ *
+ * - url === null: o hook fica parado (ainda não sei o que buscar).
+ * - dependências do efeito = [url, attempt], ambas primitivas (nunca objeto
+ * criado no corpo do componente, que seria um endereço novo a cada render).
+ * - a limpeza cancela a requisição anterior (AbortController): sem corrida.
+ * - onEvent (opcional) avisa cada etapa; fica numa REFERÊNCIA para não entrar nas
+ * dependências do efeito (uma função nova a cada render rodaria o efeito sempre).
+ */
+ export function useAxios<T>(
+ url: string | null,
+ onEvent?: (event: AxiosEvent, url: string) => void
+ ): UseAxiosResult<T> {
+ const [data, setData] = useState<T | null>(null)
+ const [error, setError] = useState("")
+ const [isLoading, setIsLoading] = useState(url !== null)
+ const [attempt, setAttempt] = useState(0)
+ const onEventRef = useRef(onEvent)
+
+ // Sem dependências: depois de toda renderização a ref passa a apontar para a função mais recente
+ useEffect(() => {
+ onEventRef.current = onEvent
+ })
+
+ useEffect(() => {
+ if (url === null) {
+ setData(null)
+ setIsLoading(false)
+ return
+ }
+
+ const target = url
+ const controller = new AbortController()
+ const request = { isPending: true }
+
+ async function load() {
+ setIsLoading(true)
+ setError("")
+ onEventRef.current?.("start", target)
+
+ try {
+ const response = await clientApi.get<T>(target, { signal: controller.signal })
+ request.isPending = false
+ setData(response.data)
+ onEventRef.current?.("done", target)
+ } catch (err) {
+ if (isCancel(err)) return
+ request.isPending = false
+ setError(getErrorMessage(err, "Erro ao carregar os dados"))
+ onEventRef.current?.("error", target)
+ }
+
+ setIsLoading(false)
+ }
+
+ load()
+
+ // Limpeza: só cancela se a requisição ainda está no ar (abort numa que já terminou não faz nada)
+ return () => {
+ if (!request.isPending) return
+
+ controller.abort()
+ onEventRef.current?.("abort", target)
+ }
+ }, [url, attempt])
+
+ // Só muda um estado: quem faz o trabalho é o efeito (a transição de estados)
+ function refetch() {
+ setAttempt(current => current + 1)
+ }
+
+ return { data, error, isLoading, refetch }
+ }
componente chama useAxios<T>(url, onEvent?)
│
├─ useState data · error · isLoading · attempt ← estados do COMPONENTE
├─ useRef onEventRef ← função mais recente, sem renderizar
├─ useEffect [url, attempt] → GET (AbortController) ← a ação da transição
└─ devolve { data, error, isLoading, refetch }

o GET termina → setData(...) → o componente roda de novo com o data novo
AbortController: o cancelamento de uma requisição em andamento

efeito roda → const controller = new AbortController()
clientApi.get(url, { signal: controller.signal }) ← entrega o signal

a url muda antes da resposta chegar:
limpeza roda → controller.abort() ← o signal avisa a requisição
a requisição rejeita → CanceledError ← catch: if (isCancel(err)) return
efeito roda de novo → NOVO controller, NOVA requisição

Genérico

useAxios<T> não sabe o que a API devolve; quem usa informa useAxios<PaginatedResponse<Task>> e o data sai tipado T | null.

Dependências primitivas

[url, attempt]: uma string e um número. Um objeto de config criado no corpo do componente seria um endereço novo a cada render e o efeito rodaria sem parar.

url === null

O hook fica parado: ainda não sei o que buscar.

O que é o AbortController

É uma API nativa do navegador (a mesma do fetch): não é do React e não é do Axios. O Axios só aceita receber o signal e respeita o cancelamento.

Como usar

new AbortController() dentro do efeito; o signal vai na requisição ({ signal: controller.signal }); o abort() vai na limpeza. Um controller por requisição: depois de abortado ele não serve de novo, por isso cada execução do efeito cria o seu.

Por que cancelar

O usuário escolhe A e, antes da resposta, escolhe B. Sem o abort(), se a resposta de A chegasse depois da de B, a tela mostraria as tasks de A sob o nome de B (condição de corrida). Com o cancelamento, a resposta velha nunca vira estado.

isCancel(err)

A requisição cancelada rejeita (CanceledError) e cairia no catch. O isCancel(err) separa "cancelei de propósito" de "deu erro de verdade" e sai sem mostrar mensagem de erro.

abort não desfaz o servidor

Cancelar só faz o navegador parar de esperar e fechar a conexão. Se o servidor já recebeu o pedido, ele pode terminar de processar: por isso o abort serve para GET (ler), e não para "desfazer" um POST.

request.isPending

const request = { isPending: true } é um objeto (não um let); vira false quando a resposta chega ou dá erro. A limpeza só chama abort() se ainda estiver pendente: abortar o que já terminou não faz nada, e assim o log do laboratório só mostra CANCELADO de verdade.

onEvent numa ref

O onEvent é uma função declarada no componente: a cada renderização é um endereço novo no heap. Se ele entrasse em [url, attempt], o efeito rodaria a cada render. A useRef guarda a função mais recente (onEventRef.current) e o efeito sem dependências só atualiza esse ponteiro depois de cada renderização: o efeito do GET enxerga sempre o callback atual, sem depender dele.

refetch

Só muda attempt; quem refaz o GET é o efeito (a transição de estados).

Async no efeito

A função passada ao useEffect não é async (devolveria uma Promise); a load() é declarada dentro e chamada em seguida.

HookLab: o nosso useAxios funcionando na tela

O HookLab chama o useAxios duas vezes (a lista de usuários e as tasks do escolhido) e registra no log tudo o que o hook avisa pelo onEvent.

src/resources/js/components/HookLab.tsx
+ import { useState } from "react"
+ import type { AxiosEvent } from "../hooks/useAxios"
+ import { useAxios } from "../hooks/useAxios"
+ import type { PaginatedResponse, Task, User } from "../types/api"
+ import { HookStatePanel } from "./HookStatePanel"
+ import { EventLog } from "./EventLog"
+
+ function wait(ms: number) {
+ return new Promise<void>(resolve => setTimeout(resolve, ms))
+ }
+
+ // Valor derivado sem let: a url das tasks depende de quem foi escolhido e do botão de erro
+ function buildTasksUrl(selectedId: number | null, isBroken: boolean): string | null {
+ if (isBroken) return "/rota-que-nao-existe"
+ if (selectedId === null) return null
+
+ return `/users/${selectedId}/tasks?page=1&limit=20`
+ }
+
+ const LABELS: Record<AxiosEvent, string> = {
+ start: "GET começou ",
+ abort: "GET CANCELADO",
+ done: "GET chegou ",
+ error: "GET falhou ",
+ }
+
+ // A tela do nosso hook: o useAxios que escrevemos, funcionando e contando o que faz
+ export function HookLab() {
+ const [selectedId, setSelectedId] = useState<number | null>(null)
+ const [isBroken, setIsBroken] = useState(false)
+ const [events, setEvents] = useState<string[]>([])
+
+ // Hook 1: a lista de usuários. Hook 2: as tasks do usuário escolhido (url null = parado)
+ const users = useAxios<PaginatedResponse<User>>("/users?page=1&limit=5")
+
+ const tasksUrl = buildTasksUrl(selectedId, isBroken)
+
+ function handleEvent(event: AxiosEvent, url: string) {
+ const time = new Date().toLocaleTimeString("pt-BR")
+ setEvents(current => [...current, `${time} ${LABELS[event]} ${url}`])
+ }
+
+ const tasks = useAxios<PaginatedResponse<Task>>(tasksUrl, handleEvent)
+
+ function handleChoose(id: number) {
+ setIsBroken(false)
+ setSelectedId(id)
+ }
+
+ function handleRefetch() {
+ tasks.refetch()
+ }
+
+ function handleBreak() {
+ setIsBroken(true)
+ }
+
+ // Troca de usuário 3 vezes seguidas: as duas primeiras requisições ainda estão no ar e são canceladas
+ async function handleRush() {
+ const list = users.data?.data ?? []
+ setIsBroken(false)
+
+ for (const user of list.slice(0, 3)) {
+ setSelectedId(user.id)
+ await wait(5)
+ }
+ }
+
+ function handleClear() {
+ setEvents([])
+ }
+
+ return (
+ <div className="d-flex flex-column gap-4">
+ <section className="card card-body">
+ <h2 className="h5">1. Hook da lista de usuários</h2>
+ <HookStatePanel
+ isLoading={users.isLoading}
+ error={users.error}
+ hasData={users.data !== null}
+ count={users.data?.data.length ?? 0}
+ />
+ <div className="d-flex flex-wrap gap-2 mt-3">
+ {users.data?.data.map(user => (
+ <button key={user.id} className="btn btn-outline-primary btn-sm" onClick={() => handleChoose(user.id)}>
+ {user.name}
+ </button>
+ ))}
+ </div>
+ </section>
+
+ <section className="card card-body">
+ <h2 className="h5">2. Hook das tasks (url: {tasksUrl ?? "null, parado"})</h2>
+ <HookStatePanel
+ isLoading={tasks.isLoading}
+ error={tasks.error}
+ hasData={tasks.data !== null}
+ count={tasks.data?.data.length ?? 0}
+ />
+ <div className="d-flex flex-wrap gap-2 mt-3">
+ <button className="btn btn-secondary btn-sm" onClick={handleRefetch}>refetch()</button>
+ <button className="btn btn-warning btn-sm" onClick={handleRush}>Trocar 3x rápido (AbortController)</button>
+ <button className="btn btn-danger btn-sm" onClick={handleBreak}>Forçar erro</button>
+ </div>
+ </section>
+
+ <section className="card card-body">
+ <div className="d-flex justify-content-between align-items-center mb-2">
+ <h2 className="h5 mb-0">3. O que o hook contou</h2>
+ <button className="btn btn-outline-secondary btn-sm" onClick={handleClear}>Limpar</button>
+ </div>
+ <EventLog events={events} />

+ )
+ }

│
├─ useAxios<PaginatedResponse<User>>("/users?page=1&limit=5") ← hook 1: estados próprios
│
└─ useAxios<PaginatedResponse<Task>>(tasksUrl, handleEvent) ← hook 2: estados próprios
tasksUrl = null (parado) | /users/ID/tasks | /rota-que-nao-existe

Trocar 3x rápido: setSelectedId(1) → espera 5 ms → setSelectedId(2) → 5 ms → setSelectedId(3)
url 1: efeito dispara o GET (log: começou)
url 2: LIMPEZA aborta o GET de 1 (log: CANCELADO) → GET de 2 (começou)
url 3: LIMPEZA aborta o GET de 2 (log: CANCELADO) → GET de 3 (começou) → chegou

Dois hooks, dois conjuntos de estado

Cada chamada de useAxios tem os seus próprios data, error e isLoading. O hook reaproveita lógica, não dados.

url null = parado

buildTasksUrl devolve null enquanto ninguém foi escolhido: o hook não faz GET e o painel mostra "null, parado". Valor derivado numa função, sem let.

O botão Trocar 3x rápido

Muda o usuário três vezes com 5 ms entre elas: as duas primeiras requisições ainda estão no ar quando a url muda. A limpeza do efeito chama abort() e o log mostra CANCELADO; só a última resposta vira data. É o AbortController visível.

Forçar erro

Aponta o hook para uma rota que não existe: o GET falha, o hook chama setError e o painel pinta o error de vermelho.

refetch()

Muda o attempt do hook: o efeito roda de novo e o log mostra um novo "começou" (sem CANCELADO, porque a anterior já tinha terminado).

handleEvent

É recriado a cada renderização, e não faz mal: o hook o guarda numa useRef. Ele escreve no log com setEvents(current => [...current, linha]) (forma de função, array novo).
