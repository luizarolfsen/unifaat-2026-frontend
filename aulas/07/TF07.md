## Objetivo

Na tela de tarefas, permitir **criar uma tarefa e atribuí-la a outro
usuário**. O usuário de destino é encontrado pela **API de busca**
(`POST /users/search`, Elasticsearch → ids → `WHERE IN` no Postgres), por
qualquer campo: nome, e-mail, cargo, cidade, UF ou bio.

Tudo acontece num **modal**: o usuário digita o nome da tarefa, busca a
pessoa, escolhe um dos resultados e confirma.

O backend **já está pronto**: a busca (Raio-X da aula, etapas 9 a 12) e a
criação de tarefa para um usuário (`POST /users/{idUser}/tasks`). O trabalho
é todo no frontend, em TypeScript.

## O que você precisa fazer

### 1. Botão e modal na tela de tarefas (`src/resources/tasks.html`)

- Um botão **"Nova tarefa para outro usuário"** que abre o modal. O Bootstrap
  já vem carregado pelo `app.ts`, então dá para abrir só com atributos:
  `data-bs-toggle="modal" data-bs-target="#assign-task-modal"`
- O modal (`<div class="modal fade" id="assign-task-modal">`, estrutura do
  Bootstrap 5) tem:
  - **Nome da tarefa:** `<input id="assign-task-name">`
  - **Busca do usuário:** um `<select id="assign-search-field">` com o campo
    (nome, e-mail, cargo, cidade, UF, bio) e um
    `<input id="assign-search-value">` com o texto, mais um botão "Buscar"
  - Um container para os resultados (`<div id="assign-search-results">`)
  - Uma área mostrando o usuário escolhido (`<div id="assign-selected-user">`)
  - Botões **"Cancelar"** (`data-bs-dismiss="modal"`) e **"Criar tarefa"**
    (`id="assign-task-submit"`)

O HTML do modal fica no `tasks.html`: o TypeScript **não** monta o modal com
`createElement`, só cuida da interação.

### 2. Tipos e API da busca (TypeScript)

Em `src/resources/js/types/api.ts`, crie o tipo dos filtros:

```typescript
export interface UserSearchFilters {
  name?: string;
  email?: string;
  job_title?: string;
  bio?: string;
  city?: string;
  state?: string;
  is_active?: boolean;
}
```

Crie `src/resources/js/api/userSearchApi.ts`, tipado com o generic que já
existe (a resposta da busca tem `page`, `limit`, `total` e `data`, o mesmo
formato de `PaginatedResponse<T>`):

```typescript
export async function userSearchApi(
  filters: UserSearchFilters,
  page: number,
  limit: number
): Promise<PaginatedResponse<User>>
```

Ela faz `clientApi.post("/users/search", { filters, page, limit })`.

### 3. Buscar o usuário dentro do modal

- Ao clicar em "Buscar" (ou Enter no campo), monte o filtro com o campo
  escolhido no `<select>` e o texto digitado. Ex.: campo "cidade" + "curitiba"
  vira `{ city: "curitiba" }`
- Chame `userSearchApi(filters, 1, 10)` e mostre os resultados em
  `#assign-search-results`: nome, e-mail, cargo e cidade/UF de cada um, com um
  botão **"Escolher"**
- Mostre o total encontrado ("4 usuários encontrados")
- Nenhum resultado: "Nenhum usuário encontrado"
- Texto vazio: não chame a API, peça para digitar algo
- Erro da API: mensagem no modal, sem quebrar a tela

### 4. Escolher o usuário e criar a tarefa

- "Escolher" guarda o usuário selecionado e mostra em `#assign-selected-user`
  ("Atribuir para: Ana Souza (ana.souza@example.com)")
- "Criar tarefa" só pode ser usado com **nome da tarefa preenchido** e
  **usuário escolhido**
- Crie a tarefa com a função que **já existe**:
  `taskCreateApi(usuarioEscolhido.id, { name })` →
  `POST /users/{idUser}/tasks`
- Sucesso: feche o modal (por exemplo, clicando no botão de `data-bs-dismiss`
  via código), limpe os campos e mostre uma mensagem
  ("Tarefa criada para Ana Souza")
- Se o usuário escolhido for **você mesmo**, recarregue a lista
  (`tasksListRender`) para a tarefa nova aparecer
- Erro: mensagem no modal, sem fechar

### 5. Organização

Siga o padrão do projeto:

- `js/api/userSearchApi.ts`: chamada da API
- `js/render/userSearchResultsRender.ts`: desenha a lista de resultados
- `js/listeners/assignTaskModalListeners.ts`: busca, escolha e criação
- `js/pages/tasks.ts`: registra os listeners do modal junto com os que já
  existem

## APIs disponíveis no backend

```
POST /users/search
Body: {
  "filters": { "city": "curitiba" },   ← texto: contém (LIKE '%valor%'), sem diferenciar maiúscula
  "page": 1,
  "limit": 10                          ← 1 a 100 (padrão 20)
}
→ 200 { "page": 1, "limit": 10, "total": 4, "data": [ User, ... ] }
→ 400 { "error": "Campo de busca inválido: ..." }

POST /users/{idUser}/tasks
Body: { "name": "Revisar o PR" }
→ 201 Task (com id_user = idUser)
→ 404 { "error": "User not found" }
```

Campos de texto aceitos na busca: `name`, `email`, `job_title`, `bio`,
`city`, `state` (também `is_active` e intervalos de `birth_date`/`created_at`,
que não são obrigatórios neste TF). A documentação completa está no Swagger.

## Como testar

1. Faça login (ex.: `alice.souza@example.com` / `senha123`) e abra a tela de
   tarefas
2. Abra o modal, busque por cidade "curitiba": 4 usuários
3. Teste outros campos: cargo "devops", UF "PE", bio "elastic", e-mail
   "@example"
4. Escolha um usuário, digite o nome da tarefa e crie
5. Faça logout, entre com o usuário escolhido (mesma senha `senha123`) e
   confira a tarefa na lista dele
6. Tente criar sem nome ou sem escolher usuário: não pode deixar

## Regras

- ✅ O usuário de destino **tem que** ser encontrado pela `POST /users/search`
  (não vale listar todos com `GET /users`)
- ✅ Tipar tudo, sem `any` solto: reaproveite `User`, `Task` e
  `PaginatedResponse<T>`
- ✅ Siga o padrão do projeto (`js/api`, `js/listeners`, `js/render`,
  `js/pages`)
- ✅ Sem `else` (early return, `continue` ou valor padrão antes do `if`)
- ✅ Trate erros com mensagem ao usuário
- ❌ Não altere o backend (busca e criação de tarefa já estão prontas)
- ❌ Não quebre o login, a lista, criar, concluir e excluir tarefas
- ❌ Não use frameworks além do que já existe (Bootstrap, Axios)
