## Objetivo

Implementar as operações que faltam no gerenciador de tarefas: **excluir**,
**alterar o nome** e **paginar** a listagem — tudo em **TypeScript** e usando
as rotas **contextuais** (`/me/tasks`) vistas na Seção 5 do README, em vez das
antigas `/users/{idUser}/tasks`.

## O que você precisa fazer

### 0. Migrar as chamadas de API para `/me/tasks` (pré-requisito)

Antes de mexer no resto, adapte `taskDeleteApi.ts`, `taskUpdateApi.ts` e
`tasksListApi.ts` pra usar as rotas contextuais — o backend já expõe elas
(`TaskViewContextApi` + `router.use("/me/tasks", ...)`), só falta o frontend
parar de mandar `idUser` na URL:

```typescript
// antes
export async function taskDeleteApi(idUser: number, taskId: number): Promise<void> {
  const { data } = await clientApi.delete(`/users/${idUser}/tasks/${taskId}`);
  return data;
}

// depois
export async function taskDeleteApi(taskId: number): Promise<void> {
  const { data } = await clientApi.delete(`/me/tasks/${taskId}`);
  return data;
}
```

Faça o mesmo para `taskUpdateApi` (`PUT /me/tasks/{id}`) e `tasksListApi`
(`GET /me/tasks?page=&limit=`). Como o parâmetro `idUser` sai da assinatura
dessas funções, ajuste também quem as chama (`taskDeleteHandler.ts`,
`taskToggleHandler.ts`, `tasksListRender.ts`, `pages/tasks.ts` etc.) — o
`idUser` continua existindo pra saber de quem é a lista na tela, só não vai
mais pro backend.

### 1. Excluir Tarefa (DELETE)

- Em `render/taskRender.ts`, descomente o bloco do botão "Excluir"
- Ele já está preparado pra chamar `taskDeleteHandler` — só falta importar e
  ligar o `addEventListener`
- O handler (`listeners/taskDeleteHandler.ts`) **já existe** — só precisa
  chamar `taskDeleteApi(taskId)` (sem `idUser`, depois da migração do item 0)

### 2. Alterar Tarefa (UPDATE — nome, não só concluída)

- A Aula 04 já implementou o checkbox de "concluída" (`is_done`). Agora é a
  vez do **nome**
- Adicione um botão "Editar" (ou duplo-clique no texto, sua escolha) que
  transforma o `<span>` do nome num `<input>` editável
- Ao confirmar (Enter ou botão "Salvar"), chame `taskUpdateApi(taskId, { name
  })` — a função já aceita esse campo, só falta usá-lo
- Crie um novo arquivo `listeners/taskEditHandler.ts`, seguindo o mesmo
  padrão dos outros handlers (tipar o `event`, tratar erro, recarregar a
  lista com `tasksListRender`)

### 3. Paginação

- O backend **já pagina** — `tasksListApi` recebe `{ page, limit }` e retorna
  `PaginatedResponse<Task>` (`data`, `page`, `limit`, `total`)
- O frontend **ignora isso hoje**: `tasksListRender.ts` sempre busca a
  página 1 e nunca mostra nenhum controle de navegação
- Adicione botões "Anterior" / "Próxima" (ou números de página, se preferir)
  abaixo da lista, usando `total` e `limit` pra saber quando desabilitar
  "Anterior" (página 1) e "Próxima" (última página)
- Ao trocar de página, chame `tasksListRender(idUser, novaPagina)` de novo —
  a função já aceita esse segundo parâmetro

## APIs disponíveis no backend (contextuais — idUser vem do JWT)

```
DELETE /me/tasks/{id}
  → Deleta a tarefa do usuário autenticado

PUT /me/tasks/{id}
  Body: { name?: string, is_done?: boolean }
  → Atualiza nome e/ou status (mande só o que mudou)

GET /me/tasks?page=1&limit=10
  → { data: Task[], page, limit, total }
```

> As rotas antigas (`/users/{idUser}/tasks/...`) continuam existindo no
> backend — não foram removidas — mas esse TF é sobre usar as novas.

## Regras

- ✅ Tipar tudo — sem `any` solto. Reaproveite `Task` e `PaginatedResponse<T>`
  de `types/api.ts`
- ✅ Use as rotas contextuais (`/me/tasks`), não as antigas
- ✅ Siga o padrão do projeto (`js/api`, `js/listeners`, `js/render`)
- ✅ Recarregue a lista após excluir/alterar/paginar
- ✅ Trate erros com mensagens ao usuário
- ❌ Não quebre o listar, criar e marcar como concluída (que já funcionam)
- ❌ Não pode usar frameworks além do que já existe (Bootstrap, Axios)
