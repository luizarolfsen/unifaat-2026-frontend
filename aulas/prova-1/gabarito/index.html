2Questões objetivas

Questão 1

Um servidor Nginx está configurado como abaixo. Sobre o funcionamento da diretiva try_files, assinale a alternativa correta.

server {
    listen 80;
    root /var/www;

    location / {
        try_files $uri $uri/ =404;
    }
}
  1. AO Nginx testa os três argumentos ao mesmo tempo e escolhe o que for mais adequado.
  2. BO Nginx trata =404 como o nome de um arquivo e o testa por último, depois de $uri e $uri/.
  3. CO Nginx testa os argumentos em ordem, da esquerda para a direita, e usa o primeiro que resolver para um arquivo ou diretório existente; se nenhum resolver, o =404 interrompe a busca e responde com o código 404.gabarito
  4. DO Nginx avalia =404 primeiro, por ser o mais restritivo, e só depois tenta $uri e $uri/.
  5. EMesmo que $uri exista como arquivo, o Nginx continua testando $uri/ e =404 antes de responder.

Por quêO try_files é sequencial, da esquerda para a direita, e para no primeiro argumento que resolve: $uri como arquivo, $uri/ como diretório (servindo o index). O =404 não é um arquivo: é um retorno de status, usado quando nada antes dele resolveu. A está errada (não é simultâneo), B confunde =404 com arquivo, D inverte a ordem e E ignora que a busca para no primeiro sucesso.

Questão 2

Considere o HTML e a linha de JavaScript abaixo.

<main>
  <article>
    <h2>Título</h2>
    <p id="txt">Oi</p>
  </article>
</main>
const p = document.getElementById('txt');

Qual alternativa está correta?

  1. Ap.parentElement é o <main>, pois ele é o ancestral mais externo de p.
  2. Bp.closest('article') retorna o <article> e p.closest('p') retorna o próprio p, pois closest() começa procurando no próprio elemento e sobe pelos ancestrais.gabarito
  3. Cp.closest('h2') retorna o <h2>, pois ele é o irmão anterior de p e closest() procura também entre os irmãos.
  4. Ddocument.querySelector('article').children.length é 3, pois children conta também a quebra de linha entre as tags.
  5. Ep.closest('main') retorna null, pois closest() só encontra o pai direto.

Por quêO closest() testa o próprio elemento e depois sobe pelos ancestrais até a raiz. A: o pai direto de p é o <article>. C: closest() só sobe, nunca olha irmãos, então p.closest('h2') é null. D: children só conta tags, então dá 2. E: closest() sobe quantos níveis precisar e acha o <main>.

Questão 3

Considere o menu de navegação de uma página:

<nav class="menu">
  <ul>
    <li class="item open">
      <span class="icon"></span>
      <a href="#">Início</a>
      <a href="#">Perfil</a>
    </li>
  </ul>
</nav>

Queremos selecionar apenas o link <a> que: (1) está dentro de um li.item que tenha a classe .open; e (2) aparece imediatamente depois (irmão adjacente) de um span.icon que seja filho direto desse li. Qual seletor atende a todas as condições?

  1. A.menu li.item span.icon + a
  2. B.menu li.item.open span.icon ~ a
  3. C.menu > li.item.open span.icon + a
  4. D.menu li.item.open > span.icon a
  5. E.menu li.item.open > span.icon + agabarito

Por quêli.item.open exige as duas classes no mesmo li; > span.icon exige filho direto; + a pega só o irmão imediatamente seguinte (Início). A: falta .open. B: ~ pega todos os irmãos seguintes (Início e Perfil). C: .menu > li falha, porque há um <ul> entre o nav e o li. D: o espaço antes do a procura um a dentro do span, mas o a é irmão dele.

Questão 4

Uma lista <ul id="lista"> tem vários <li>, cada um com um botão <button class="remover">. Existe um único listener de clique, registrado no <ul>. O usuário clica em um botão "remover".

lista.addEventListener('click', (event) => {
  if (event.target.tagName === 'BUTTON') {
    event.target.parentElement.remove();
  }
});

Qual alternativa explica corretamente o que acontece?

  1. Aevent.target é o <ul> e event.currentTarget é o <button>, pois o evento sobe do botão até a lista.
  2. Bevent.target e event.currentTarget são o <button>, porque o clique aconteceu nele.
  3. Cevent.target é o <li> e event.currentTarget é o <ul>, pois o <li> é o pai mais próximo do botão.
  4. Devent.target é o <button> (origem do clique) e event.currentTarget é o <ul> (dono do listener); o evento borbulha do botão até a lista, o que permite a delegação de eventos e cobre até itens criados depois.gabarito
  5. Eevent.target é o <ul>; o listener só dispararia se o clique fosse direto na lista, pois eventos não se propagam para o pai por padrão.

Por quêtarget é onde o evento nasceu (o botão clicado); currentTarget é o elemento dono do listener que está rodando (o <ul>). O clique borbulha do botão até o <ul>, por isso um único listener na lista atende todos os botões, inclusive os criados depois: é a delegação de eventos. A inverte os dois, B e C erram a origem/dono, e E nega o bubbling, que é o comportamento padrão.

Questão 5

Um card <div class="card"> possui um listener de clique que abre um modal. Dentro dele há um link <a href="/detalhes"> com um handler próprio. Ao clicar no link, queremos executar apenas o handler do link: sem navegar para /detalhes e sem abrir o modal do card.

Qual alternativa resolve o problema corretamente?

  1. AChamar event.preventDefault() (impede a navegação) e event.stopPropagation() (impede o borbulhamento até o card) no handler do link.gabarito
  2. BChamar somente event.stopPropagation(), pois ele impede tanto o borbulhamento quanto a navegação.
  3. CChamar somente event.preventDefault(), pois ele cancela o comportamento padrão e também a propagação.
  4. DRegistrar o listener do link com { capture: true }, o que impede a navegação do link.
  5. EChamar event.stopPropagation() para cancelar a navegação e event.preventDefault() para cancelar a propagação.

Por quêSão dois problemas independentes, com dois métodos independentes: preventDefault() cancela a ação padrão do navegador (seguir o href) e stopPropagation() impede o evento de subir até o card. B e C acham que um método faz o trabalho do outro; E troca os papéis; D só muda a fase em que o listener roda (captura), não cancela a navegação.

Questão 6

Sobre a relação entre window e document, assinale a alternativa correta.

  1. Adocument é o objeto global do navegador e window é uma propriedade dele.
  2. Bwindow.document e document são objetos diferentes: o segundo é uma cópia do primeiro.
  3. Cdocument é uma propriedade de window, que é o objeto global do navegador e onde vivem localStorage, fetch e eventos como resize e scroll; escrever document sem o prefixo funciona porque propriedades do objeto global são acessíveis diretamente.gabarito
  4. DlocalStorage e fetch pertencem a document, por isso só funcionam quando chamados como document.localStorage e document.fetch.
  5. EO prefixo window. é obrigatório para acessar document fora de funções; dentro de funções ele pode ser omitido.

Por quêwindow é o objeto global (a aba do navegador); document é uma propriedade dele, a página carregada. window.document === document é true: é o mesmo objeto, acessível sem prefixo em qualquer lugar do código, porque tudo que está no objeto global pode ser usado diretamente. A inverte a hierarquia, B fala em cópia, D põe localStorage/fetch no lugar errado e E inventa uma regra de escopo.

3Questões dissertativas

3.1Questão 7: benefícios do pré-compilador (2,0)

Cite pelo menos quatro benefícios práticos de usar um pré-compilador (como o Vite) no frontend e explique cada um.

3.1.1Resposta esperada

Quatro destes, cada um com a explicação (0,5 por benefício + explicação):

  • Linguagens que o navegador não entende: usar TypeScript e React/JSX, que o pré-compilador converte para JavaScript comum;
  • Minificação: arquivos menores (sem espaços, comentários e com nomes curtos), reduzindo o tráfego na internet;
  • Organização e escalabilidade: o código fica dividido em vários módulos/arquivos, e o pré-compilador junta tudo no build;
  • Bundle: unificação dos módulos JS em poucos arquivos, economizando requisições HTTP;
  • Controle de cache: assets (JS, CSS, imagens, fontes) com hash no nome do arquivo, então o navegador nunca usa uma versão velha;
  • HMR (hot module reload): as mudanças aparecem no navegador sem recarregar a página, aumentando a produtividade no desenvolvimento.

Bônus (não foi dado em aula, mas é aceito): recursos avançados de CSS com pré-processadores (Sass, SCSS etc.).

3.2Questão 8: generics em TypeScript (2,0)

Dado o trecho de código abaixo:

const usuarios = [
  { id: 1, nome: 'Ana', ativo: true },
  { id: 2, nome: 'Bruno', ativo: false }
];

function filtrar(lista, condicao) {
  const resultado = [];
  for (const item of lista) {
    if (condicao(item)) {
      resultado.push(item);
    }
  }
  return resultado;
}

const ativos = filtrar(usuarios, (u) => u.ativo);

Faça a tipagem, em TypeScript, seguindo estas regras:

  1. Crie um type Usuario que contenha id, nome e ativo (0,5)
  2. Tipar a array usuarios baseado no type Usuario (0,5)
  3. Tipar os argumentos e o retorno da função filtrar para Usuario (0,5)
  4. Inserir um generic T na função filtrar, para que ela possa ser usada com qualquer tipo de objeto, não somente Usuario. (0,5)

3.2.1Resposta esperada

// 1) Type Usuario
type Usuario = {
  id: number;
  nome: string;
  ativo: boolean;
};

// 2) Array usuarios tipada
const usuarios: Usuario[] = [
  { id: 1, nome: 'Ana', ativo: true },
  { id: 2, nome: 'Bruno', ativo: false },
];

// 3) Função filtrar tipada
function filtrar(
  lista: Usuario[],
  condicao: (item: Usuario) => boolean
): Usuario[]

// 4) Função filtrar com generics
function filtrar<T>(
  lista: T[],
  condicao: (item: T) => boolean
): T[]

Nos itens 3 e 4 só a assinatura muda: o corpo da função continua o mesmo do enunciado.
